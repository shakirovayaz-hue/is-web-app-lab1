&#x20;Модель данных (Data Model)



&#x20;1. Словарь терминов (соответствие курсу)

| Термин курса | Термин моей темы | Описание |

|---|---|---|

| Ticket | Request (Заявка) | Главная сущность: заявка на выдачу автомобиля |

| Site | Car (Автомобиль) | Справочник: доступные служебные автомобили |

| User | User (Пользователь) | Сотрудник (Руководитель, Диспетчер, Начальник) |



&#x20;2. Сущности и атрибуты



&#x20;Сущность: User (Пользователь)

\- `id` (PK, int) — уникальный идентификатор пользователя.

\- `login` (string) — логин для входа в систему.

\- `role` (string) — роль (Manager, Dispatcher, Chief).



&#x20;Сущность: Car (Автомобиль, справочник)

\- `id` (PK, int) — уникальный идентификатор автомобиля.

\- `name` (string) — марка, модель и гос. номер (например, "Toyota Camry А123АА 777").



&#x20;Сущность: Request (Заявка, главный объект)

\- `id` (PK, int) — машинный первичный ключ.

\- `number` (string) — человеческий номер заявки (например, "REQ-2026-001").

\- `title` (string) — цель поездки (заголовок).

\- `description` (string) — маршрут и детали.

\- `status` (string) — статус заявки (New, InProgress, Closed, Cancelled).

\- `carId` (FK, int) — внешний ключ на сущность Car.

\- `createdByUserId` (FK, int) — внешний ключ на User (кто создал).

\- `assigneeUserId` (FK, int, nullable) — внешний ключ на User (назначенный диспетчер). Может быть пустым при создании.



&#x20;3. Связи между сущностями

\- \*\*Car (1) → (N) Request\*\*: Один автомобиль может фигурировать в множестве заявок (история выдач).

\- \*\*User (1) → (N) Request (создатель)\*\*: Один пользователь может создать множество заявок.

\- \*\*User (1) → (0..N) Request (исполнитель)\*\*: Один пользователь (диспетчер) может быть назначен на множество заявок. У новой заявки исполнитель отсутствует (0).



&#x20;4. Проверка Третьей нормальной формы (3НФ)

Название и характеристики автомобиля (поле `name`) хранятся в сущности `Car` только один раз. В сущности `Request` хранится только внешний ключ `carId`. При изменении гос. номера или модели автомобиля данные обновляются в одной строке таблицы `Car`, текст не дублируется в каждой исторической заявке, что исключает аномалии обновления и соответствует 3НФ.
